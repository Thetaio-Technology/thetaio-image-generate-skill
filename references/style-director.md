# 风格指挥

## 目标

把用户的视觉需求转成可执行的生图方案。风格指挥只决定视觉表达,不改变用户给定的事实、文字和品牌约束。

## 决策顺序

1. 明确用途: 封面、海报、插画、卡片、头像、产品图、素材、背景图。
2. 明确画面主体: 人物、物品、场景、信息结构、需要出现或避免出现的元素。
3. 明确输出格式: 单张或批量,尺寸,横竖比,是否需要透明背景。
4. 明确风格来源: 用户指定风格、参考图或参考文件中的风格库。
5. 写 `style-plan.md`: 记录风格、色彩、构图、字体/文字、负向约束、批量一致性规则。
6. 再写提示词文件和 `tasks.json`。

## 风格选择

- 用户明确指定风格时,优先使用用户指定风格。
- 用户提到小红书、封面、知识卡、种草、教程卡片时,加载 `xiaohongshu-styles.md`。
- 用户没有指定平台,但要求封面、海报、概念图、知识卡、产品图时,加载 `general-styles.md`。
- 用户给参考图时,优先使用图生图锁定风格或构图。
- 用户只说“好看一点”时,先选择保守通用风格: 清晰主体、干净背景、自然光、明确层次、不过度装饰。

## 批量一致性

批量图片必须共享:

- 主风格
- 主色板
- 画幅比例
- 光线和材质语言
- 字体和排版倾向

只有主题、镜头、局部元素和信息层级可以变化。需要多风格探索时,在 `style-plan.md` 明确每组风格边界。

## 降低 AI 味

- 避免塑料 3D、过度辉光、意义不明的大光效。
- 避免模板化居中构图连续重复。
- 给主体留出呼吸空间,不要把所有元素塞满。
- 可使用轻微手绘、真实材质、自然阴影和局部不规整来增加可信度。
- 图片中文字越短越好; 长解释放在图外文案或说明中。

## 生成前自检

- 提示词是否明确主体、构图、风格、色彩、尺寸。
- 是否写清楚不能出现的元素。
- 如果有参考图,任务是否走图生图。
- 批量图是否有一致性规则。
- 输出路径是否全部落在用户指定目录或默认 `image-output/`。
- 用户是否只是要提示词; 如果是,不要执行脚本。
