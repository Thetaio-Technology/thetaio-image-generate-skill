# 生成后处理

用于图片已经生成后,需要为发布、分享、传输或归档做轻量压缩。后处理不是生图核心流程,只有用户要求“压缩、瘦身、发布包、上传前处理、小红书发布图、转 WebP/JPEG/PNG”时才执行。

## 上传前自动压缩(与后处理不同)

参考图在上传前会做一次**自动边界判断**,这一步默认开启,不需要用户要求,也不属于这里说的“后处理”:

- 单张参考图 **> 4MB** 时,去 alpha 转 **JPEG(q90,保留原分辨率)** 再上传; 否则原样上传。
- 目的是缩小请求体。网关会把整个请求体读进内存并放大数倍,超大参考图并发时会 OOM。
- 只影响上传的参考图,不改原始文件; 关闭用 `--no-compress`。

下面的“压缩”指的是对**生成输出图**做的后处理。

## 处理原则

- 保留 `raw/` 原图,不要覆盖生成结果。
- 压缩图放到 `compressed/` 或用户指定目录。
- 默认不自动压缩;只有用户明确要求时才执行。
- 默认优先输出 `webp`,质量 `80`;用户要求 PNG/JPEG 时按用户要求。
- 小红书发布图如果担心兼容性,可输出 JPEG 或 PNG;如果只是本地分享和存档,优先 WebP。
- 压缩失败时报告真实错误,不要删除原图。

## 内置脚本

使用本技能自带脚本:

```bash
python "<技能目录>/scripts/compress_image.py" \
  "<输出目录>/raw" \
  --output "<输出目录>/compressed" \
  --format webp \
  --quality 80
```

递归压缩目录:

```bash
python "<技能目录>/scripts/compress_image.py" \
  "<输出目录>/raw" \
  --output "<输出目录>/compressed" \
  --format webp \
  --quality 80 \
  --recursive
```

## 常用参数

| 参数 | 作用 | 建议 |
| --- | --- | --- |
| `--output` / `-o` | 输出目录或文件 | 批量时写 `compressed/` |
| `--format` / `-f` | `webp`、`png`、`jpeg` | 默认 `webp` |
| `--quality` / `-q` | 压缩质量 0-100 | 默认 80,发布图可用 85-90 |
| `--recursive` / `-r` | 递归处理目录 | 目录批量压缩时开启 |
| `--suffix` | 同格式输出后缀 | 默认 `-compressed` |
| `--overwrite` | 允许覆盖原图 | 只有用户明确要求时使用 |
| `--json` | 输出 JSON 结果 | 自动化验收时开启 |

## 输出结构

```text
<输出目录>/
  raw/
    01.png
    02.png
  compressed/
    01.webp
    02.webp
```

## 何时压缩

- 用户明确说“压缩、转 WebP、瘦身、发小红书前处理”。
- 用户要一个可交付发布包,并且图片体积明显偏大。
- 批量图片用于上传、网页、分享或归档。

## 何时不压缩

- 用户只要求原始生图。
- 用户需要继续图生图迭代,此时保留最高质量原图。
- 用户要求无损 PNG 或必须保留原始像素文件。

## 输出约束

- 文件输入且未指定 `--output` 时,压缩图写在原图旁边;同格式会自动追加 `-compressed`。
- 目录输入且指定 `--output` 时,压缩图写到输出目录,并保留递归相对路径。
- 默认不会覆盖原图;需要覆盖时必须显式加 `--overwrite`。
- 执行压缩不需要 API Key,也不会调用图片生成接口。

## 完成报告字段

如果执行了压缩,回复里补充:

```text
后处理: 已压缩
压缩格式: <webp/png/jpeg>
压缩目录: <输出目录>/compressed
原图目录: <输出目录>/raw
```
